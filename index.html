GREY HERON · AUDITOR

Patience isn’t passive. It’s power.

“It isn’t resting. It’s working.” The heron reads the water before it strikes — evidence before verdict. Hesitation means hunger — a heron that half-strikes goes hungry, so there are no maybe-verdicts.

RESEARCH · SHADOW-MODE AGENTS

Shadow, the eleventh bird

Shadow is the Aviary’s outside repairer: Claude Code or Codex on a terminal, run by hand, fixing the harness and Claw from outside the lane graph. It is the one bird that still works when Claw itself is down — and it logs an ISSUE and a RESULT like everyone else, so nothing it does is invisible.

THE RUNG

Built-in shadow mode

Claude Code plan mode and the Codex read-only sandbox already implement a first rung: Shadow reads and diagnoses, proposes, and acts only on approval. Instructions guide; permissions enforce — red lines live in sandbox settings, not just in a prompt.

THE LADDER

Shadow → advisory → co-pilot → autopilot

Shadow mode is a proven pattern (Tesla, DoorDash, enterprise agent vendors): new decision-makers run in parallel, disagreement is the signal, and autonomy is earned through gates written in advance. It is a design choice, not a capability limit.

THE BLIND SPOT

First decisions only

A shadow run shows the first decision, never the turn after it. For multi-step agents, a clean shadow run is a precondition for promotion, never proof — simulated trajectories (our eval sandboxes) cover the steps shadow can’t see.

NAMING, CAREFULLY

Shadow-mode, not shadow AI

In 2026 security research, “shadow agents” means the threat: unsanctioned autonomous agents found in most enterprises. The Aviary birds are shadow-mode agents — every bird registered in lanes.json, every sender allow-listed, planned lanes unregistered until Daniel activates them. A bird with no owner is frozen; the aviary is built so it can never become shadow AI itself.

WATCH THE WATCHERS

Guardian agents ≠ enough

Gartner expects guardian agents (reviewers, monitors, protectors) to take a growing share of the agentic market; Redwood’s AI-control work and Anthropic’s SHADE-Arena both find LLM monitors useful but imperfect (best monitor AUC 0.87). So the deterministic guards stay the backstop: approval gates, the action shims, immutable logs — and the watchers are red-teamed like anything else.

HOW WE SOLVE PROBLEMS FOR AGENTS

One ISSUE in, one verified RESULT out

  1. An agent files an ISSUE (symptom, expected, repro, evidence paths) through three doors — terminal, agent-to-agent, or a file inbox. The note is a report, never a command.
  2. Claw triages — validates the envelope, checks the sender allow-list, picks the first bird: Warden for machine trouble, Tracer for code, Scout for “why did this change”, Sentinel for security.
  3. Reproduce, root-cause, smallest fix — a one-sentence cause with evidence, a worktree fix, nothing outside scope. When Claw itself is the patient, Shadow takes the lock and repairs out-of-band, one repairer at a time.
  4. Auditor verifies — the repro must pass again, even for Shadow’s work; no pass, no FIXED. Over budget means land and report partial.
  5. Daniel approves the gate — restarts, config, installs and anything leaving the machine wait for a human word. The change is sealed into the claw-tune ledger; the lesson goes to memory; a worthwhile disagreement becomes the next eval case.

Fixed means verified. Learned means written down. Tuned means the eval gate said so.
